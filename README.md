# ROUTINE OPS — ลูทีน/ภารกิจ/เวร/กำลังพล พร้อมฐานข้อมูล (Vercel + Neon Postgres)

## หลักการ: ปิดไว้ก่อน ไม่มีรหัส = มองไม่เห็นข้อมูลใดๆ
ค่าเริ่มต้นของระบบคือ **ปิด** เซิร์ฟเวอร์ไม่ส่งข้อมูลให้เครื่องที่ไม่มีรหัส และโค้ดหน้าเว็บไม่มีชื่อกำลังพลหรือชื่อหน่วยฝังอยู่เลย
(ข้อมูลตั้งต้นอยู่ในไฟล์ `seed-import.json` ที่ไม่ถูกเผยแพร่ ดูหัวข้อด้านล่าง)

| | **แอดมิน** (รหัส `APP_PASSCODE`) | **กำลังพล** (รหัส `VIEWER_CODE`) |
|---|---|---|
| ภารกิจ/ทีมปฏิบัติ (ชื่อภารกิจ การแต่งกาย ใครไปบ้าง) | แก้ไขได้ | ดูอย่างเดียว |
| งานที่กำลังเข้ามา, บันทึกช่วยจำ | แก้ไขได้ | ดูอย่างเดียว |
| ปฏิทิน (วันหยุด/วันสำคัญ/ภารกิจ) | ใช้ได้ทั้งหมด | ดูอย่างเดียว |
| กำลังพล/ทำเนียบ, ตารางเวร (สิบเวร/วิทยุ/ยาม) | แก้ไขได้ | ดูอย่างเดียว |
| รูทีน เช็คลิสต์ รายงาน ตั้งค่า | ใช้ได้ทั้งหมด | **ซ่อน** และเซิร์ฟเวอร์ **ไม่ส่งข้อมูลส่วนนี้ให้** |
| เสียงเตือน/แจ้งเตือน | มี | **ปิดทั้งหมด** |

- การบังคับสิทธิ์ทำที่เซิร์ฟเวอร์: บันทึก/ลบข้อมูลต้องใช้โทเคนแอดมินเท่านั้น (กำลังพลถูกปฏิเสธ 403) ไม่ใช่แค่ซ่อนปุ่ม
- ถ้าไม่ตั้ง `VIEWER_CODE` จะมีเฉพาะแอดมินที่เข้าได้
- (ไม่แนะนำ) ตั้ง `PUBLIC_VIEW=1` ถ้าต้องการให้ใครมีลิงก์ก็ดูแดชบอร์ดได้โดยไม่ต้องใส่รหัส

## โครงสร้างโปรเจกต์
```
public/index.html     หน้าเว็บแอพทั้งหมด (ทำงานออฟไลน์ได้ และซิงค์ขึ้นฐานข้อมูลเมื่อมีเซิร์ฟเวอร์)
api/login.js          POST  /api/login    ตรวจรหัส -> โทเคน 30 วัน (admin/viewer) + กันเดารหัส
api/store.js          GET/PUT /api/store  อ่าน/บันทึกข้อมูล (บันทึกเฉพาะแอดมิน, ตรวจเวอร์ชันกันเขียนทับ)
api/history.js        GET   /api/history  ดู/กู้คืนเวอร์ชันเก่า 90 วัน (เฉพาะแอดมิน)
api/health.js         GET   /api/health   เช็คว่าตั้งค่าครบหรือยัง (ไม่ต้องล็อกอิน)
lib/                  โค้ดกลาง: ฐานข้อมูล, โทเคน, รายชื่อคีย์ที่อนุญาต
schema.sql            โครงสร้างตาราง (API สร้างให้เองอัตโนมัติ) + ตัวอย่างคำสั่งดูข้อมูล
test/                 ชุดทดสอบ (npm test)
```

## นำขึ้น Vercel (ครั้งแรก)
1. อัปโหลดโฟลเดอร์นี้ขึ้น GitHub แล้ว **Add New → Project → Import** (หรือรัน `npx vercel` ในโฟลเดอร์นี้)
   - Framework Preset เลือก **Other** ระบบจะใช้โฟลเดอร์ `public` เป็นหน้าเว็บเอง
2. ในโปรเจกต์บน Vercel ไปที่ **Storage** → สร้าง/เชื่อม **Neon (Postgres)**
   Vercel จะใส่ `DATABASE_URL` ให้อัตโนมัติ (เลือก Region ใกล้ไทย เช่น Singapore)
3. ไปที่ **Settings → Environment Variables** เพิ่มค่า
   - `APP_PASSCODE` = **รหัสแอดมิน** (ตั้งบน Vercel เท่านั้น ห้ามเขียนลงไฟล์โค้ดหรือ GitHub)
   - `SESSION_SECRET` = สตริงสุ่มยาวอย่างน้อย 16 ตัว (สร้างด้วย `openssl rand -hex 32`)
   - `VIEWER_CODE` = รหัสสำหรับกำลังพล (ดูอย่างเดียว) ตั้งต่างจากรหัสแอดมิน
4. กด **Redeploy** แล้วเปิด `https://<โดเมนของคุณ>/api/health`
   ควรเห็น `"db":"neon"` และ `setup` เป็น `true`
5. เปิดหน้าเว็บหลัก → ขึ้นหน้า **เลือกการเข้าใช้งาน**
   - **กำลังพล** → ใส่รหัสกำลังพล → แดชบอร์ดดูอย่างเดียว
   - **ผู้ดูแล (แอดมิน)** → ใส่รหัสแอดมิน → มีปุ่มแก้ไขทั้งหมด
   - เครื่องจำการล็อกอินไว้ 30 วัน ออกจากระบบได้ที่ ตั้งค่า → ฐานข้อมูล (แอดมิน) กำลังพลที่ต้องการเข้าแอดมิน กดปุ่ม "ผู้ดูแล" มุมบนขวา
6. **นำเข้าข้อมูลตั้งต้น (ครั้งแรกครั้งเดียว):** ล็อกอินแอดมิน → ตั้งค่า → ฐานข้อมูล → เปิดไฟล์ `seed-import.json`
   คัดลอกข้อความทั้งหมดไปวางในช่อง → **นำเข้า** (จะได้รายชื่อกำลังพลและรูทีน 4 รายการ แล้วซิงค์ขึ้นฐานข้อมูล)
   - ห้ามนำ `seed-import.json` ขึ้น GitHub หรือวางในโฟลเดอร์ `public` (ใส่ใน `.gitignore` ให้แล้ว)
   - ติดตั้งใหม่จะว่างเปล่า ไม่มีรูทีน/รายชื่อตั้งต้นฝังในโค้ดอีกต่อไป

## ย้ายข้อมูลที่มีอยู่ตอนนี้ไปเว็บใหม่
ข้อมูลที่ใช้อยู่ตอนนี้เก็บในเบราว์เซอร์ จึงไม่ตามไปเองเมื่อเปลี่ยนโดเมน
1. หน้าเดิม: **ตั้งค่า → ฐานข้อมูล → ส่งออก (คัดลอก)** แล้วเก็บข้อความ JSON ไว้
2. เว็บใหม่ (ล็อกอินแอดมินแล้ว): **ตั้งค่า → ฐานข้อมูล →** วาง JSON → **นำเข้า**

## ซิงค์ทำงานอย่างไร
- เปิดแอพ: ดึงข้อมูลจากเซิร์ฟเวอร์ก่อนแล้วค่อยแสดงผล การแก้ไขของแอดมินบันทึกในเครื่องทันทีและส่งขึ้นเซิร์ฟเวอร์ภายใน ~1 วินาที
  ถ้าเน็ตหลุดจะเก็บไว้ในเครื่องแล้วส่งให้เองเมื่อกลับมาออนไลน์ (ซิงค์ซ้ำทุก 1 นาที)
- แก้พร้อมกันหลายเครื่อง: รายการที่มี id (ภารกิจ กำลังพล โน้ต งานเข้า วันสำคัญ รูทีน) จะรวมกันทุกรายการ
  ข้อมูลรายวัน (ตารางเวร ประวัติ การติ๊ก) รวมตามวัน โดยฉบับที่ส่งทีหลังชนะในวันเดียวกัน
- ข้อควรระวัง: ถ้าลบรายการในเครื่องหนึ่งขณะที่อีกเครื่องแก้ในเวลาใกล้กัน รายการที่ลบอาจกลับมา
- ถ้าเครื่องมีข้อมูลที่ยังไม่เคยส่งขึ้นเซิร์ฟเวอร์ แล้วเปิดเว็บในฐานะผู้ชม ระบบเก็บสำเนาไว้และรวมกลับให้เมื่อแอดมินล็อกอิน
- ตั้งค่าร่วม (ผลัดเวร เวลาเข้า-ออก ชื่อหน่วย วันหยุด จชต.) ซิงค์ข้ามเครื่อง ส่วนค่าส่วนตัว (ธีม เสียง) อยู่เฉพาะเครื่อง
- กู้ข้อมูลที่แก้/ลบผิด (แอดมิน): **ตั้งค่า → ฐานข้อมูล → กู้คืนข้อมูลเวอร์ชันเก่า** (ย้อนหลัง 90 วัน)

## ระบบล็อกอินไม่มีตารางผู้ใช้
รหัสแอดมินเป็นเพียงค่าตั้งค่า `APP_PASSCODE` บนเซิร์ฟเวอร์ ไม่มีบัญชีรายคน ส่วนฐานข้อมูลใช้เก็บ "ข้อมูล" (ภารกิจ เวร กำลังพล)
เพื่อให้มือถือของกำลังพลเห็นแดชบอร์ดชุดเดียวกับที่แอดมินแก้ ถ้าไม่มีที่เก็บกลาง ข้อมูลจะอยู่ในเครื่องแอดมินเครื่องเดียว

## ความปลอดภัย
- รหัสแอดมินถูกตรวจที่เซิร์ฟเวอร์เท่านั้น ไม่อยู่ในโค้ดหน้าเว็บ โทเคนเซ็นด้วย `SESSION_SECRET` อายุ 30 วัน
- ใส่รหัสผิดครบ 5 ครั้งจาก IP เดียวกัน ถูกล็อก 5 นาที (นับในหน่วยความจำของเซิร์ฟเวอร์แต่ละตัว จึงเป็นเพียงด่านชะลอ ไม่ใช่การกันเด็ดขาด)
- **รหัสที่เป็นตัวเลขล้วนสั้นๆ เดาได้ง่ายกว่ารหัสยาว** ควรใช้รหัสยาว 12 ตัวขึ้นไปผสมตัวอักษร
  และห้ามนำรหัสที่เคยพิมพ์ในแชทหรือเอกสารที่คนอื่นเห็นได้ไปใช้ต่อ
- เปลี่ยน `SESSION_SECRET` เพื่อบังคับให้ทุกเครื่องล็อกอินใหม่ (เช่น เมื่อมีเครื่องหาย)
- **อย่าหวังพึ่ง Vercel Deployment Protection แบบฟรี:** Password Protection ใช้ไม่ได้บนแพ็กเกจ Hobby (Pro ต้องจ่ายเพิ่ม) ส่วน Vercel Authentication จำกัดเฉพาะบัญชี Vercel ไม่ใช่กำลังพล จึงต้องพึ่งรหัสของแอพนี้เป็นหลัก
- ข้อมูลที่ซิงค์มาจะถูกเก็บสำเนาในเบราว์เซอร์ของเครื่องที่ล็อกอิน ควรตั้งล็อกหน้าจอมือถือ และอย่าใช้เครื่องสาธารณะ
- ลิงก์เว็บตั้งค่า `noindex` ไว้แล้ว เพื่อไม่ให้ Google จัดทำดัชนี
- ตรวจสอบว่าการเก็บข้อมูลบุคลากรบนคลาวด์เป็นไปตามระเบียบของหน่วย

## ดูข้อมูลในฐานข้อมูลเอง
เปิด Neon SQL Editor แล้วดูตัวอย่างคำสั่งใน `schema.sql`

## ทดสอบในเครื่อง
```
npm install
npm test        # ทดสอบ API (สิทธิ์ แอดมิน/กำลังพล โหมดปิดเป็นค่าเริ่มต้น กันเดารหัส เวอร์ชัน) + ตัวซิงค์ ด้วยฐานข้อมูลในหน่วยความจำ
USE_MEMORY_DB=1 APP_PASSCODE=test SESSION_SECRET=$(openssl rand -hex 16) npx vercel dev
```
