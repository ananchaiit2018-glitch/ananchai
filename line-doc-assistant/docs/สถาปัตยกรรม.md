# สถาปัตยกรรม LINE Smart Document Assistant

## 1. ผลการตรวจสอบโปรเจกต์ที่มีอยู่ (ข้อ 12.1–12.2)

ใน repository นี้มีระบบทะเบียนหนังสือที่ใช้งานอยู่แล้ว คือ `digital-book-register/` (Node.js + SQLite) ทำงานบนคอมสำนักงานที่ `http://localhost:3000`

**ระบบใหม่นี้ไม่แตะระบบเดิมเลย** ไม่แก้โค้ด ไม่เปิดฐานข้อมูล `data/register.db` โดยตรง — ส่งข้อมูลเข้าเฉพาะผ่านหน้าเว็บ (เหมือนเจ้าหน้าที่กรอกเอง) ด้วย Playwright เท่านั้น

ข้อสังเกตจากโค้ดจริงของระบบเดิม (ใช้ออกแบบ Adapter ภายหลัง — ยังไม่เชื่อมต่อใน Demo Mode):

| เรื่อง | ระบบเดิมทำงานอย่างไร | ผลต่อการออกแบบ |
|---|---|---|
| เลขทะเบียน | ระบบเดิม**ออกเลขเอง**ตอนกดบันทึก (กันเลขซ้ำในฐานข้อมูล) | ระบบใหม่**ไม่กำหนดเลขทะเบียน** อ่านเลขที่ได้จากหน้าจอผลลัพธ์แทน |
| ช่องบังคับ | ต้องมี "เรื่อง" "ลงวันที่" และ "ชื่อผู้รับหนังสือ/ผู้บันทึก" | นอกจาก 4 ช่องที่อ่าน หน้าตรวจสอบต้องให้เจ้าหน้าที่กรอก **เรื่อง** และเลือก**ผู้บันทึก** |
| เข้าระบบ | รหัสผ่าน (ถ้าตั้งไว้) + เลือกผู้เข้าเวร | Adapter ต้องเข้าระบบด้วยรหัสที่เก็บนอกซอร์สโค้ด และเลือกผู้เข้าเวรตามผู้ยืนยัน |
| กันลงซ้ำ | ขึ้นกล่อง "หนังสือนี้อาจลงซ้ำ" | Adapter ต้อง**หยุดและแจ้งเจ้าหน้าที่** ห้ามกด "บันทึกต่อ" เอง |
| แนบไฟล์ | ช่องแนบไฟล์ PDF/JPG/PNG ในฟอร์ม | แนบไฟล์ต้นฉบับที่ตรวจ sha256 แล้ว |

> ชื่อช่อง/ปุ่มจริงจะยืนยันจาก URL และภาพหน้าจอที่ผู้ดูแลส่งมา ก่อนเปิดใช้ Adapter จริง (ไม่เดาเอง)

## 2. ภาพรวมการทำงาน

```
เจ้าหน้าที่ (มือถือ)
   │  ส่ง PDF / รูป ในแชท LINE OA
   ▼
LINE Platform ──HTTPS + X-Line-Signature──► [เซิร์ฟเวอร์รับเอกสาร]  (FastAPI)
                                              ├─ ตรวจลายเซ็น LINE + รายชื่อผู้มีสิทธิ์
                                              ├─ ตรวจชนิด/ขนาด/ความปลอดภัยไฟล์ → เก็บ + sha256
                                              ├─ อ่าน OCR (Tesseract ไทย / ข้อความใน PDF)
                                              ├─ สร้างรายการ "รอตรวจสอบ"
                                              └─ Dashboard: ตรวจ / แก้ไข / ยืนยัน / ยกเลิก
                                                     │ (เฉพาะรายการที่ยืนยันแล้ว)
                                                     ▼
                              [ตัวรับงานคอมสำนักงาน] (office agent) ── ดึงงานเอง (ขาออก HTTPS + token)
                                              ├─ ดาวน์โหลดไฟล์ → ตรวจ sha256 → เก็บในเครื่อง
                                              ├─ Adapter: เปิดเว็บทะเบียนเดิม → กรอก → แนบไฟล์ → บันทึก
                                              ├─ อ่านผลจากหน้าเว็บจริง (เลขทะเบียน) + ตรวจซ้ำในหน้าทะเบียน
                                              └─ รายงานผล → เซิร์ฟเวอร์แจ้ง LINE
```

ใน Demo Mode ทั้งสองส่วนทำงานบนเครื่องเดียว LINE ถูกจำลอง และ Adapter เป็น "ทะเบียนจำลอง" (ไม่แตะเว็บจริง)

## 3. สถานะของงาน (ไม่มีการส่งซ้ำอัตโนมัติ)

```
received → reading → review ──ยืนยัน──► confirmed ──คอมสำนักงานรับงาน──► processing ──► done
                       │                    │                                  └──► failed
                       └──ยกเลิก──► cancelled └──ยกเลิก──► cancelled
reading ──อ่านไม่ได้──► review (ทุกช่อง "กรุณาตรวจสอบ")
```

- รับงานแบบ "จองครั้งเดียว" (`UPDATE … WHERE status='confirmed'`) คอมสำนักงาน 2 เครื่องก็ไม่ได้งานเดียวกัน
- `failed` และ `processing` ที่ค้าง **ไม่ถูกส่งซ้ำเอง** — เจ้าหน้าที่ต้องตรวจในเว็บทะเบียนจริงก่อน แล้วเลือก "ยืนยันว่าบันทึกแล้ว" หรือ "ส่งให้คอมสำนักงานอีกครั้ง" (พร้อมคำเตือน)
- ข้อความ LINE ซ้ำ (LINE ส่ง webhook ซ้ำได้) ถูกกันด้วย `message_id` ที่ไม่ซ้ำ

## 4. ทางเลือกการติดตั้งจริง (ต้องให้ผู้ดูแลเลือก)

| | A. ทุกอย่างบนคอมสำนักงาน + อุโมงค์ HTTPS (แนะนำ) | B. เซิร์ฟเวอร์คลาวด์ + ตัวรับงานในสำนักงาน |
|---|---|---|
| HTTPS สำหรับ webhook | Cloudflare Tunnel / ngrok (ฟรี ไม่ต้องเปิดพอร์ต) | ใบรับรองของเซิร์ฟเวอร์ |
| เอกสารอยู่ที่ไหน | คอมสำนักงาน (ผ่าน LINE ระหว่างทางเท่านั้น) | เซิร์ฟเวอร์คลาวด์ชั่วคราว + คอมสำนักงาน |
| เงื่อนไข | คอมสำนักงานต้องเปิดและต่อเน็ตตลอด | มีค่าเซิร์ฟเวอร์ และต้องดูแลความปลอดภัยเพิ่ม |

โค้ดรองรับทั้งสองแบบ เพราะตัวรับงานคุยกับเซิร์ฟเวอร์ผ่าน HTTPS + token เสมอ

## 5. ความปลอดภัย

- ตรวจ `X-Line-Signature` (HMAC-SHA256 ด้วย Channel secret) ทุกคำขอ ไม่ผ่าน = ตอบ 401 ไม่ทำอะไร
- รับเฉพาะ LINE User ID ที่อยู่ในรายชื่อผู้มีสิทธิ์
- ตรวจชนิดไฟล์จาก**เนื้อไฟล์** (ไม่เชื่อนามสกุล) · จำกัดขนาด · ปฏิเสธ PDF ที่มีรหัสผ่าน/สคริปต์/ไฟล์ฝัง · จำกัดจำนวนหน้าและขนาดภาพ
- เก็บไฟล์ด้วยชื่อที่ระบบสร้าง (ไม่ใช้ชื่อจากผู้ส่ง) + sha256 · ตรวจ sha256 อีกครั้งหลังคัดลอกไปคอมสำนักงาน · ลบสำเนาบนเซิร์ฟเวอร์ได้เฉพาะเมื่อยืนยันแล้วว่าคอมสำนักงานเก็บสำเร็จ
- รหัส/token ทั้งหมดอยู่ในไฟล์ `.env` / `data/secrets.env` (ไม่อยู่ในซอร์สโค้ด ไม่ขึ้น git)
- Dashboard ต้องเข้าสู่ระบบรายบุคคล (รหัสผ่านเข้ารหัส scrypt) · คุกกี้ SameSite=Strict + ตรวจ Origin กัน CSRF
- บันทึกประวัติทุกขั้น: ผู้ส่ง เวลา ผู้แก้ไข ผู้ยืนยัน ผลการบันทึก
- **ไม่ส่งเอกสารให้ AI ภายนอก** — Claude API ปิดไว้และยังไม่ได้เขียนส่วนเชื่อมต่อ จะทำเมื่อผู้ดูแลอนุมัติเท่านั้น

## 6. ข้อจำกัดที่ต้องทราบ

- เอกสารที่ส่งผ่าน LINE จะผ่านเซิร์ฟเวอร์ของ LINE (นอกประเทศ) — **ห้ามส่งหนังสือชั้นความลับ** ทางช่องทางนี้
- LINE OA แผนฟรีส่งข้อความแจ้งเตือน (push) ได้จำกัดต่อเดือน ข้อความ "ได้รับเอกสารแล้ว" ใช้ reply (ไม่นับโควตา) ส่วนข้อความแจ้งผลใช้ push
- OCR ภาษาไทยอ่านตัวเลขไทยผิดได้ จึงทำเครื่องหมาย "กรุณาตรวจสอบ" ทุกช่องที่ความมั่นใจต่ำ และบังคับให้คนยืนยันทุกครั้ง
